# Plan: 0.2.0

This is the canonical release request and roadmap. Completed implementation tasks are summarized
here; the remaining release work is tracked under [`0.2.0/`](./0.2.0/).

## Release goals

The release establishes no-throw endpoint execution and adds client-level and call-level headers
with a JSON Accept default. Invalid initialization fails immediately with typed exceptions.

## Success criteria

- Recoverable endpoint-execution failures are returned as typed Results.
- A client can be created once and receive a different authorization token on every endpoint call.
- JSON is requested by default without preventing explicit header overrides.
- README limitations, usage documentation, and changelog match the shipped behavior.

## Priority convention

Task filenames start with a three-digit priority: `001_...`, `002_...`, and so on. A lower number
means the task should be taken earlier. The number is execution order, not an issue identifier.

When priorities change, rename the files and update this index. Keep gaps if inserting work would
otherwise cause unnecessary renames. A task must not start while one of its declared dependencies is
unfinished.

## Execution order

| Priority | Task                                          | Status | Dependency |
| -------- | --------------------------------------------- | ------ | ---------- |
| 003      | [Release integration](./0.2.0/003_release.md) | active | none       |

Implemented in this release:

- typed exceptions for invalid client configuration and API definitions;
- no-throw endpoint execution for recoverable request, transport, HTTP, and response failures;
- client-level and call-level headers with deterministic precedence and removal semantics;
- default JSON `accept` and conditional JSON `content-type` headers.

## Deferred

Convenience timeouts are tracked in [`0.3.0.md`](./0.3.0.md). Callers can use the existing `signal`
option with `AbortSignal.timeout()` and `AbortSignal.any()` until that release.

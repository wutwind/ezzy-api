# Plan: 0.4.0 — HTTP errors

This release makes non-2xx responses easier to inspect and narrow without introducing endpoint-aware
generic error contracts. Detailed tasks live under [`0.4.0/`](./0.4.0/).

## Execution order

| Priority | Task                                                      | Status  | Dependency |
| -------- | --------------------------------------------------------- | ------- | ---------- |
| 001      | [HTTP error metadata](./0.4.0/001_http_error_metadata.md) | ready   | 0.3.0      |
| 002      | [Error exports and guards](./0.4.0/002_error_guards.md)   | ready   | 001        |
| 003      | [HTTP error recipes](./0.4.0/003_error_recipes.md)        | ready   | 001–002    |
| 004      | [Release integration](./0.4.0/004_release.md)             | pending | 001–003    |

## Success criteria

- HTTP failures expose headers, raw body, and best-effort parsed JSON.
- Individual error types and safe guards are exported publicly.
- Documentation covers header inspection, JSON validation, and narrowing unknown failures.

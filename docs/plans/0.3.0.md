# Plan: 0.3.0 — Timeout

This release adds a convenience timeout API on top of the existing signal-based cancellation
mechanism. Detailed tasks live under [`0.3.0/`](./0.3.0/).

## Release goal

Provide a library-owned deadline with a typed `TimeoutError`, while preserving caller cancellation
as a distinct outcome. The design must define total-call versus per-attempt behavior before any
implementation begins.

## Execution order

| Priority | Task                                                        | Status                     | Dependency |
| -------- | ----------------------------------------------------------- | -------------------------- | ---------- |
| 001      | [Timeout design and implementation](./0.3.0/001_timeout.md) | design discussion required | 0.2.0      |
| 002      | [Release integration](./0.3.0/002_release.md)               | pending                    | 001        |

## Success criteria

- Client and call-level timeout configuration has unambiguous override semantics.
- Timeout and caller cancellation produce distinct typed failures.
- The deadline behavior across interceptors and retries is documented and tested.
- `TimeoutError` and `isTimeoutError` are exported publicly.
- Existing signal composition remains supported and documented.
